比較対象:

- Phase 1 renderer: `episodes/002_myna_app/work/efficiency_test/scene_###.png`

## 1. 計測方法

すべて1920×1080で計測した。字幕帯を除く `y=0..899` をアクティブ領域とし、次のラスタ指標を使った。

- **非白色率**: 白背景から離れた画素の割合。画面の情報量・詰まり具合の代理値。
- **暗色率**: 濃紺などの暗色画素の割合。見出しと本文の視認要素の代理値。
- **見出しインク帯**: `y=50..619` の暗色画素を行方向にまとめた帯。フォントの指定値ではなく、画像上で見える文字の高さ・幅の代理値。
- **色面積率**: 彩度のある画素の割合。図形やカードなどの色面の代理値。
- **最大色ブロック**: 粗い120×90グリッドで見た最大の色ブロック。主ビジュアルの候補を確認する補助値であり、文字や淡い背景を完全には分離しない。
- **公式素材の占有率**: 既存の公開候補用合成指定にある公式素材ボックスの面積。実際の公式画面は画像の余白を含むため、表示された文字の面積そのものではない。

計測結果の機械可読版は `episodes/002_myna_app/work/scene_renderer_analysis/baseline_metrics.json`、代表8シーンの比較は `episodes/002_myna_app/work/scene_renderer_analysis/representative_comparison.json` に保存した。

| 色面積率 | 4.93% | 4.92% | 色の量だけでは差が見えない。面の配置と文字サイズが主な差 |
| 見出しインク帯の平均高さ | 218.7px | 113.7px | 多行タイトルや図形を含む代理値。次の代表表で行帯も確認する |
| 見出しインク帯の平均幅 | 945px | 1,028px | Phase 1 は横幅を使うが、縦の階層が弱い |

非白色率は、単純に情報を増やすことが良いという意味ではない。教師データの17.31%に対してPhase 1は29.56%で、同じ1920×1080の中に淡色カード、枠、補助文を詰め込みすぎていることを示す。Phase 1.5では、情報量を減らしながら見出しと公式画面の一要素を大きくする方向に寄せる。

## 4. 教師データとPhase 1の見た目の差

教師データは、上端の青いルール、広い余白、大きな濃紺の見出し、1つの主ビジュアルという構成が中心である。公式画面を合成する前の空きスロットも、左または右に十分な幅を持つ「主役の場所」として設計されている。

一方、Phase 1の contact sheet では次の傾向が繰り返される。

- すべてのレイアウトが小さな見出し・説明・カードの組み合わせに見え、シーンごとの視線の置き場が弱い。
- 公式画面が小さく、読ませたい文字が縮小表示になる。
- list / compare の枠・影・背景面が面積を使い、PowerPointのカード一覧に寄る。
- 連続するcontact sheetのラベルがセル下部から次の行へ食い込み、シーン番号と見出しの対応が読み取りにくい。
- 旧Pillow分岐では、公式素材を持つ `layout_03_visual_text` の一部で素材を主ビジュアルとして配置していない。

## 5. 公式画面の占有目標

既存の公開候補用合成ボックスを基準にすると、代表シーンの公式素材領域はアクティブ領域の13〜37%（scene 001, 005, 010, 014, 022, 027）である。scene 027は左右2枚で37.01%あり、比較として読ませやすい大きさに近い。scene 001のアイコンは公式画面ではないため10.21%でも成立する。

Phase 1.5の目標は次の通りとする。

- 読ませる公式スクリーンは、1枚なら画面全体の35〜55%を目安に置く。縦長端末画面は幅だけでなく高さを確保し、文字が潰れる場合は `official_asset_crop` の指定範囲を優先する。
- 2枚比較は各画像を無理に小さくせず、左右の面積を確保する。説明文を足すより、画像中の公式ラベルを読めることを優先する。
- アイコン・図解などの主ビジュアルは、内容領域の30〜60%を使える大きさにする。ただし字幕帯 `y=900..1079` には侵入しない。
- 公式画像がないシーンは、空きカードを増やさず、図形・番号・短い強調文のいずれか1つを主役にする。

## 6. Phase 1.5で実装する判定基準

episode.jsonは変更せず、layout・scene id・既存の公式素材情報から安全なデフォルトを導出する。

| チェック | 目標 / WARN条件 |
|---|---|
| 見出し | 通常80〜100px、強調100〜140px、WARNは60px未満 |
| 二次説明 | 48〜60pxを基本、40px未満はWARN |
| 主ビジュアル | アクティブ領域の30〜60%を目安、25%未満はWARN |
| 公式画像 | 読ませる画面は35〜55%目安、25%未満はWARN |
| カード | 4枚以上はWARN。枠線と影を主役にしない |
| 情報密度 | 非白色率70%超、または本文の小要素が連続する場合はWARN |
| 安全領域 | 字幕帯への侵入、画面外、素材同士の重なりはFAIL相当 |

## 7. 改修範囲

この分析後に変更するのは、Phase 1.5で許可された範囲に限る。

- `templates/scenes/` の8レイアウトと `styles.css`: 余白を残しつつ見出し・主ビジュアル・公式画面を大きくする。
- `scripts/scene_renderer.py`: Pillowの自動フィット、日本語折返し、公式素材の大きなcrop、素材数に応じた二列配置、レイアウトごとの主役比率を改善する。HTML/CSS分岐にも同じ階層を反映する。
- renderer専用の計測・品質レポート・テスト: v2出力のWARNを機械的に可視化する。

Episode 001、Episode 002の既存最終動画、ナレーション、`episode.json`、発音辞書、字幕計画、production preflightの判定思想は変更しない。Episode 003、動画の再制作、YouTube公開も行わない。

## 8. 結論

Phase 1 rendererの主なギャップは、画像生成の有無ではなく、同じ画面に置く要素の優先順位である。Phase 1.5では8レイアウトを維持し、見出しを80〜100px級に固定し、主ビジュアルまたは公式画面を1つ大きく見せ、カード・小文字・装飾を減らす。v2を再レンダリングした後、機械的なWARNを確認しても、最終判断は人間がcontact sheetで行う。
